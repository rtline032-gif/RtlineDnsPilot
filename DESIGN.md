# RtlineDnsPilot 0.1.12

User-approved scope: Windows 10/11 local DNS intermediary, editable ordinary DNS/DoH profiles, direct HTTPS reachability probes, stable automatic selection, statistics, all-unavailable notification, exact restoration of adapter DNS. Do not alter VPN, proxies, routes, IP addresses, adapter state, or Wi-Fi connection. Development and verification must not change the real adapter DNS or install/start a Windows service.

The UI runs without administrator privileges. Monitoring can run alone. Enabling management installs a local automatic Windows service through an explicit UAC action in the application. The elevated installer copies the application to an administrator-writable-only Program Files directory. A named pipe, restricted to the installing user and SYSTEM, exposes status/configuration/enable/disable/select commands. The service owns loopback UDP and TCP DNS listeners, profiles, probes, selection and a write-ahead DNS restoration journal. Service recovery restarts it after a crash. At each service start it restores an incomplete old transaction before considering a new activation. Disabling restores DNS before stopping the relay; normal service stop does the same. A restoration error preserves the journal and blocks new activation.

The service uses the selected adapter GUID, resolves its current index at each mutation, snapshots IPv4 and enabled IPv6 DNS source (automatic/static) and ordered address list. It sets only DNS to 127.0.0.1 and ::1 using netsh, verifies results, and records the transaction before any mutation. Any partial failure triggers rollback. Do not restore over a third-party replacement of DNS; expose a conflict. Do not silently turn a DoH profile into plaintext. On all-profile failure keep monitoring, show an alert once per incident, retain or restore the original network state as appropriate; do not cycle through settings indefinitely.

Profiles use explicit upstream/bootstrap IPv4/IPv6 addresses. DoH uses HTTPS with normal TLS certificate validation and the provider hostname as SNI, pinned bootstrap connectivity and no system-DNS bootstrap recursion. UDP falls back to DNS-over-TCP on a truncated response. The relay accepts only local queries, validates transactions and question matching, preserves TTLs, uses bounded concurrency and deadlines, and does not log browsing DNS questions. The operating system supplies DNS caching.

The default probe is HTTPS GET https://chatgpt.com/cdn-cgi/trace through DNS answers from each profile, without cookies or account credentials. A 2xx or 3xx response proves public HTTPS reachability only; 401/403/429/5xx are separate failure/degraded states and not a working Codex session. Authenticated Codex inference and WebSocket activity are not exercised. Existing connections and application DNS caches may delay reconnection after a switch. Latency means DNS/HTTPS response time, not bandwidth or model generation speed. Tailscale and any other existing routing can influence results and is left alone.

Selection: retain current profile after one or two failed rounds, switch on three consecutive failures to an alternative with two fresh successful rounds; emergency failover bypasses the five-minute minimum dwell time. Automatic optimization prioritizes a higher observed successful-check ratio, even if that channel has a higher delay. It requires five confirmed consecutive successful rounds and five-minute dwell; with equal observed reliability, switching for speed alone requires at least 20% lower rolling latency. Success evidence must belong to the current target context with a fresh last result and no stale gap across the required sequence. Explicit manual fixation and preferred-channel choices retain their documented precedence. Statistics retain up to 120 measured samples per profile and expose sample counts, successful-check percentage, mean/p95 response time, failures, last result and switch history. This is observed availability, not a promised SLA.

UI: Russian, editable list, probe status and history, add/edit/delete/import/export profiles, interface selector, monitor/pause, enable/disable system management, restore, manual pin/automatic selection, notification area icon. Closing hides to the tray; explicit Exit explains whether service management continues. Clearly distinguish monitoring from applied system DNS and HTTPS reachability from verified Codex operation.
