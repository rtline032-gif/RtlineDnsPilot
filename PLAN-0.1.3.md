# RtlineDnsPilot 0.1.3 implementation plan

Goal: add selectable ChatGPT/Gemini monitoring, right-click manual channel fixation and deletion, a blue active row, and fully red failed history bars.

Design: extend the current config and RPC contracts; keep the existing service/relay architecture and the 15 public profiles. No real DNS changes, service installation or restart during development.

1. Monitoring: persist MonitorChatGpt (legacy/default true), MonitorGemini (default false) and up to six custom named HTTPS targets, require at least one selected service. ChatGPT keeps the editable ProbeUrl; Gemini uses https://gemini.google.com/. All tests are anonymous public HTTPS reachability, not authenticated generation. All selected services must pass for an automatic candidate. Flatten selected profile/service pairs into the existing four concurrent probe slots. Record each service's result and an aggregate; preserve old history and filter selection evidence by selected endpoints.
2. Manual control: ManualProfileId plus nullable ManualUntil (UTC; null means permanent). Fixation bypasses automatic failover and reports unavailability. Timed expiry returns to automatic selection. SelectAsync(null) clears both manual fixation and the existing soft preference. Validate enabled channel references. Deleting/disabling a fixed channel clears its fixation.
3. UI: checkboxes in settings; per-service status columns; right-click select the clicked row, fix permanently/5/15/60 minutes, return to auto, delete. Apply an active blue row without hiding failed service text. Render failed bars fully red, preserve good DNS/HTTPS stacking.
4. Compatibility: preserve legacy channels, IDs, pending drafts and history. Require an updated service for new monitoring/manual features; never silently apply them to a service that ignores the new fields. Remap manual IDs during local/service handoff.
5. Validation: meaningful config/selection/aggregation/concurrency/persistence/manual-expiry tests; existing protocol/rollback/RPC suite; render settings, channel and journal views with synthetic data. Public Gemini endpoint verified from the official domain; live probes optional, no account credentials.
6. Connection controls: periodic status requests do not block buttons; persistent pause/resume reaches the service and cancels active probes without stopping its DNS relay. One-off checks do not resume a paused monitor. Retry a lost connection after 2/5/10/30 seconds, expose read-only reconnect and confirmed repair/restore, retain last confirmed data without claiming a local choice is applied. Do not start a duplicate automatic observer while service state is unknown. Bound projected status below 4 MiB while retaining all numeric points and disk history; allow a bounded 1 MiB configuration request.
7. Automatic DNS: selected physical adapter only, confirmed UAC, protected journal before DHCP writes, verify source rather than a fixed lease, roll back partial failures. Stop management first and leave the service disabled until explicit enable/update.
8. Release: product/assembly/runtime names RtlineDnsPilot 0.1.3, preserve legacy service/data identities for upgrades and explicitly replace the service executable path. Allowlisted clean runtime/source ZIPs with all 15 public channels, neutral docs and checksums. Inspect archive bytes for local identifiers and diagnostics, extract and verify the final package.

Execution continues under the user's existing instruction; no extra implementation-choice or design approval is needed.
