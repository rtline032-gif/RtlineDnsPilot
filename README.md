# RtlineDnsPilot

Бесплатная программа для Windows 10/11 x64: проверяет DNS и доступность выбранных HTTPS-сервисов, сравнивает каналы, сохраняет историю и может автоматически выбирать доступный DNS-профиль.

**Версия 0.1.11 — ранний выпуск без цифровой подписи.** Подготовка заявки SignPath Foundation не означает, что фонд уже одобрил проект или подписал программу. Статус указан в [политике подписи](CODE_SIGNING.md).

## Скачать и обновить

[Скачать RtlineDnsPilot 0.1.11 для Windows x64](https://github.com/rtline032-gif/RtlineDnsPilot/releases/download/v0.1.11/RtlineDnsPilot-0.1.11-win-x64.zip). Нужен .NET Desktop Runtime 10.0 x64. Распакуйте весь архив в одну папку.

В 0.1.10 добавлена отдельная кнопка «Обновить программу»: она проверяет опубликованные выпуски этого репозитория, скачивает более новую версию и проверяет SHA-256, состав ZIP и версию программы. Помощник ждёт закрытия прежнего окна и запускает новое. Пользовательские каналы и история сохраняются. Если уже установлена служба, её обновление потребует разрешения Windows и завершится режимом наблюдения, с выключенным управлением DNS.

Для версий до 0.1.10 нужен один ручной переход на этот архив: в старом приложении кнопки обновления нет. Новая версия также сохраняет исправления 0.1.9 для восстановления DNS после тайм-аута и обработки позднего ответа отключившемуся DNS-клиенту.

Локально пройдены 66 проверок восстановления/автоматического DNS и три изолированных запуска GUI. Полный C# прогон: 441 PASS и один ранее существовавший сбой CurrentUser DPAPI в ограниченном профиле. Реальные установка службы, UAC и изменение DNS физического адаптера при этих проверках не выполнялись. Обновление на конкретном проблемном Windows 11 требует проверки на самом ПК. Состояние проверки на GitHub видно во вкладке Actions.

## Исправления 0.1.11

Конфликт IPv6 больше не блокирует восстановление принадлежащего программе IPv4. Кнопка «DNS автоматически (DHCP)» принимает уже выбранный и проверенный автоматический DNS того же адаптера.

При обновлении из 0.1.10 кнопкой «Обновить программу» новый установщик сначала полностью останавливает принадлежащую службу. Он сохраняет уже подтверждённый автоматический DNS, защищённо архивирует прежний снимок в локальном каталоге данных и восстанавливает остальные принадлежащие программе настройки. Установщик не принуждает сторонний статический DNS к DHCP. Повреждённые журналы, незавершённые системные команды и смена настроек во время восстановления продолжают блокировать обновление.

После успешного обновления управление DNS выключено, служба работает в режиме наблюдения. Каналы и история сохраняются. Обычное «Восстановить DNS» сохраняет прежнюю цель — точные исходные настройки; оно сообщает о конфликте с ручным изменением.

## Возможности

- Обычный DNS (UDP/TCP) и DNS-over-HTTPS. Поле DoH необязательно.
- 15 встроенных публичных профилей, свои каналы, проверка дубликатов, импорт и экспорт JSON.
- Отдельный выбор проверок: ChatGPT / Codex, Gemini, страница входа Tailscale и до шести собственных публичных HTTPS-адресов.
- Автовыбор по стабильности или задержке с защитой от частых переключений; ручная фиксация канала постоянно или на время.
- Цветные результаты, графики за выбранный период и размер одного столбика, журнал событий.
- По отдельному нажатию «Поделиться DNS» — отправка подходящих дополнительных публичных DNS в каталог владельца проекта. Условия передачи описаны в [PRIVACY.md](PRIVACY.md).

## Запуск и управление DNS

Нужен [.NET Desktop Runtime 10.0 x64](https://dotnet.microsoft.com/en-us/download/dotnet/10.0). Распакуйте все файлы выпуска в одну папку и запустите `RtlineDnsPilot.exe`. Подробные действия по запуску и обновлению: [README.txt](README.txt).

В режиме наблюдения системный DNS не меняется. Для управления DNS выберите физический Wi-Fi/Ethernet-адаптер и нажмите «Включить управление DNS». Программа запросит разрешение Windows, установит фоновую службу `NetPilotDns`, сохранит исходные DNS и направит DNS выбранного адаптера на локальный посредник. Служба может продолжать работу после закрытия окна.

«Отключить управление» и «Восстановить DNS» возвращают сохранённые исходные DNS. «DNS автоматически (DHCP)» задаёт автоматическое получение DNS выбранного адаптера. Пауза останавливает проверки; это отдельное действие от восстановления DNS.

Для удаления сначала восстановите DNS и завершите главное окно через «Выход». Затем из папки программы в PowerShell запустите встроенный помощник удаления службы; потребуется разрешение Windows:

```powershell
Start-Process -FilePath (Resolve-Path .\RtlineDnsPilot.exe).Path -ArgumentList '--uninstall-service' -Verb RunAs -Wait
```

После успешного удаления службы можно удалить папку программы. При конфликте с внешними настройками программа сохраняет журнал восстановления и сообщает ошибку: не удаляйте его до разрешения конфликта.

## Что означают проверки

Успешная публичная HTTPS-проверка не доказывает работу входа в аккаунт, генерации ИИ, WebSocket Codex или VPN-туннеля Tailscale. Для успешного общего результата должны пройти все выбранные проверки. Задержка в миллисекундах не означает скорость загрузки в Мбит/с.

Программа не меняет VPN, прокси и маршруты. Доверие к стороннему DNS-провайдеру пользователь выбирает самостоятельно. HTTPS-сертификаты проверяются обычными средствами .NET; приложение не предлагает их отключать.

## Сборка и проверки

Требуются Windows x64, .NET SDK 10.0 и Node.js 24 для локальных проверок приёмника.

```powershell
pwsh ./build.ps1
node ./receiver/google-apps-script/receiver-tests.cjs
```

`build.ps1` собирает приложение и запускает проверки C# перед копированием четырёх файлов программы в `artifacts`. Для запуска рядом нужны также `profiles.json`, `README.txt` и `CHANNELS.txt`; добавьте `LICENSE`, `PRIVACY.md` и `CODE_SIGNING.md` при распространении новой сборки.

Автоматическая сборка GitHub Actions публикует отдельный архив без подписи. Проверки используют изолированные данные и подставные системные операции: их успех не является проверкой реального изменения DNS или установки службы на физическом адаптере.

## English overview

RtlineDnsPilot is an open-source Windows DNS monitor and local DNS forwarder. It probes public DNS and HTTPS reachability through configurable upstream profiles, records history, and supports automatic selection by stability or latency. System DNS management is explicitly enabled by the user and requires Windows elevation. Public probes do not verify authenticated AI sessions or VPN tunnels.
