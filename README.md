# RtlineDnsPilot

Локальное приложение для Windows: проверяет DNS-каналы и публичные HTTPS-адреса ChatGPT, Gemini, Tailscale и своих сервисов, сохраняет историю и выбирает доступный канал с приоритетом стабильности или времени отклика.

[Скачать выпуски](https://github.com/rtline032-gif/RtlineDnsPilot/releases) · [Лицензия MIT](LICENSE)

## Обновление 0.1.31

При включённом управлении и автовыборе Pilot дополнительно проверяет, может ли DNS Windows разрешить имена выбранных сайтов. При сбое Pilot очищает кэш DNS и повторяет запрос. Если это не помогло, он пробует один подтверждённый резервный канал. Если резерва нет или ошибка сохраняется, Pilot восстанавливает исходный DNS адаптера и переходит в режим наблюдения. После такого восстановления управление можно включить вручную.

## Обновление 0.1.22

«Откатить обновление» открывает версию, которая была установлена перед последним завершённым обновлением через программу. Откат работает из сохранённой копии без интернета. Если установлена служба, Windows запросит разрешение. Помощник сначала восстановит исходный DNS, затем вернёт файлы службы из защищённой копии. После отката управление DNS выключено. Настройки и история остаются на месте. Если нужная копия отсутствует или повреждена, программа остановит откат и покажет причину.

Откат сохраняется при обычном запуске программы. Чтобы снова перейти на свежий выпуск, нажмите «Обновить программу» в предыдущей версии.

## Исправления DNS и диагностика 0.1.21

При фатальной остановке локального DNS-посредника восстановление DNS Windows выполняется независимо от паузы проверок и межраундового ожидания. При ошибке сохраняется журнал и явное состояние необходимости восстановления. Самопроизвольного возобновления управления после отказа нет.

«Диагностика посредника» читает ограниченные метаданные фактических запросов relay: QTYPE/class, локальный UDP/TCP и IPv4/IPv6, профиль/контекст, наблюдавшиеся upstream-попытки, этапы и DNS-коды заголовка. В памяти хранятся 32 последних завершения и 32 негативных/ошибочных результата за пять минут; QNAME, пакеты и токены не записываются, данные не отправляются через «Поделиться DNS». Чтение не создаёт новых сетевых проб. Это не подтверждение Windows getaddrinfo, доставки приложению или работы авторизованного Codex.

Подпись «HTTPS ChatGPT» уточняет границы публичной проверки. Диалог DHCP отдельно объясняет остановку и отключение службы. Причина конкретных обрывов Codex с VPN по имеющемуся архиву ещё не установлена.

## Обновление 0.1.20

При отдельной установке или обновлении службы проверяется версия ответившего процесса. Старая или неизвестная версия не считается успешным обновлением и не получает настройки или команду включения DNS. Вверху окна рядом показаны версии программы и подключённой службы; без связи версия службы отмечается как неподтверждённая.

Сетевой сбой проверки GitHub не мешает кнопке «Обновить программу» обновить старую службу из уже имеющейся программы. Результат обновления службы и непроверенное наличие нового выпуска показываются отдельно.

Обычное обновление программы уже включает замену установленной службы и проверку её живого ответа с нужной версией. Заранее отключать управление вручную не требуется. Windows запросит разрешение; после обновления службы управление DNS включают отдельной кнопкой. Сохранённые каналы и история сохраняются. Доступность кнопки исправления/обновления сама по себе не доказывает старую службу — она также предлагается при потере связи.

## Обновление 0.1.19

Кнопка «Обновить программу» получает исправления и обновлённый каталог без отдельного импорта. При переходе с полного набора 0.1.18 добавляются четыре новые конфигурации: два Bezmezhau с опубликованным primary 143.20.64.55 и два Comss DoH по официальному mobileconfig и инструкции роутера. Прежние каналы, пользовательские параметры, ID, заметки, выбор и история сохраняются; обычный набор из 26 становится набором из 30. Эквивалентные записи повторно не добавляются. Сохраняется предел 32 канала и явное уведомление о недостающих добавлениях при заполненной базе.

Краткая ошибка теперь сохраняет первую и последнюю наблюдавшиеся IP-причины: предшествующий IPv4 TLS-тайм-аут виден и при последующей ошибке IPv6 TCP. Полная «Диагностика канала» по-прежнему содержит все попытки. Сертификаты, тайм-ауты, порядок IP и критерии успеха не менялись. Новые и прежние базовые адреса исключаются из клиентского «Поделиться DNS».

Публикация параметров владельцем не подтверждает работоспособность в вашей сети. Внешние TCP/TLS-отказы этим выпуском не объявляются устранёнными. Динамический bootstrap Zapret остаётся отдельной доработкой. После обновления службы управление DNS выключено; включите его отдельной кнопкой.

## Обновление 0.1.18

«Диагностика канала» открывает последнее сохранённое измерение выбранного канала: отдельные ответы A/AAAA, возвращённые адреса и выполненные попытки к каждому целевому IP с этапами TCP, TLS и HTTP-заголовков, временем и фактической версией HTTP. Отказ IPv6 до TCP, незавершённый TLS, отклонение сертификата и сброс после TLS показываются раздельно; предыдущие IP-попытки сохраняются. Просмотр и копирование отчёта не запускают новую проверку и не меняют сеть. Для старых измерений подробности честно отмечены как отсутствующие.

Диагностика не меняет тайм-ауты, порядок IP, проверку сертификатов и критерий публичной HTTPS-доступности. Полные фазовые записи сохраняются только у последнего измерения и читаются отдельно для одного канала, чтобы не перегружать обычные ответы службы. История числовых результатов и статистика автовыбора сохраняются.

Каталог проверен 17.11.2026. Xbox выключен в новом наборе с предупреждением о временном отказе; старые статические Zapret-профили сохранены с предупреждением о текущем DoH через Cloudflare без постоянного IP. Программа пока требует явные bootstrap-IP: динамический режим Zapret этим патчем не добавляется. Существующие пользовательские каналы и их включённое состояние не изменяются; исправление метаданных не возвращает удалённые записи.

Внешние отказы TCP/TLS, установленные в переданной диагностике без VPN, этим патчем не объявляются устранёнными. Исследование использовало Node HTTP/1.1; его результаты не заменяют проверку штатного HTTP/2. Для обновления используйте «Обновить программу». Подробности от фоновой службы доступны после её обновления до 0.1.18 и нового штатного измерения.

## Обновление 0.1.17

Рабочие каналы со свежими успешными результатами расположены сверху таблицы: сначала более стабильные, затем с меньшим временем ответа. Порядок хранения каналов, галочки, выбранный канал и история сохраняются.

«Переподключить приложения» предлагает выбрать Chrome и/или Codex. С разрешением Windows помощник очищает системный DNS-кэш и вручную сбрасывает внешние TCP/IPv4-соединения HTTPS выбранных приложений текущего пользователя в этом сеансе. Окна остаются открыты; текущие запросы и соединения других вкладок выбранного Chrome прерываются. Приложению может потребоваться повтор запроса или обновление страницы. IPv6, QUIC и внутренний DNS-кэш приложений не сбрасываются; иногда полный перезапуск всё равно потребуется. Сброс не запускается автоматически при смене канала. DNS-настройки адаптера, VPN, прокси, маршруты и служба этой кнопкой не перенастраиваются.

В 0.1.12 и новее версия доступна через «Обновить программу». Реальный сброс соединений и UAC при разработке не выполнялись; проверки сброса используют фиктивные платформы, нативное чтение процессов и TCP-таблиц проверено отдельно на Windows 10.

Версия распространяется через кнопку «Обновить программу» в 0.1.12 и новее. Сетевые причины отказа других DNS этим исправлением автоматически не устраняются.

## Запуск

- `win-x64`: Windows 10/11 x64, Microsoft .NET Desktop Runtime 10 x64.
- `win7-x64`: Windows 7 SP1 x64, Microsoft .NET Desktop Runtime 6.0.36 x64. Это вариант совместимости с неподдерживаемой Microsoft платформой; нативные проверки Windows 7 выполняются отдельно.

Первый переход с выпуска без кнопки обновления: завершите прежнюю программу через «Выход», распакуйте весь подходящий ZIP в отдельную папку и запустите `RtlineDnsPilot.exe`. В 0.1.12 и новее кнопка «Обновить программу» использует публичный `updates.json` этого репозитория. Старые 0.1.10/0.1.11 используют GitHub API и зависят от его доступности и лимитов. Не смешивайте файлы разных версий и вариантов Windows.

Окно работает без прав администратора. Для включения управления системным DNS используется локальная служба с разрешением Windows. При обновлении установленной службы DNS восстанавливается, новый каталог добавляется к её конфигурации и управление остаётся выключенным. Автоматическое повторное включение управления не выполняется.

## Границы проверки

Успешный результат означает доступность публичного HTTPS-адреса через выбранный DNS. Вход в аккаунт, генерация ответа, WebSocket и активная сессия Codex не проверяются. Работоспособность и безопасность стороннего DNS не гарантируются; успешные результаты из одной сети не переносятся на другую. VPN, прокси, маршруты, IP-адрес и подключение Wi-Fi приложение не изменяет.

Режим DoH сохраняет обычную проверку сертификатов и имени сервера; открытый DNS не используется как скрытый fallback. Кнопка «Поделиться DNS» отправляет владельцу проекта только подходящие дополнительные публичные DNS после успешной публичной проверки ChatGPT/Gemini. Автоматической отправки при запуске или обновлении нет. Подробнее: [PRIVACY.md](PRIVACY.md), [README.txt](README.txt), [CODE_SIGNING.md](CODE_SIGNING.md).

## Сборка

`./build.ps1` собирает приложение и запускает проверки. Для Windows 7: `./build.ps1 -Windows7 -LegacySdkDirectory <каталог SDK с packs .NET 6.0.36>`; компилятор .NET SDK 10 используется для современного синтаксиса C#. Проверки используют отдельные каталоги и фиктивные службы; реальные DNS/служба Windows при разработке не меняются.
