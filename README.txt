ИСПРАВЛЕНИЕ В 0.1.11: ВОССТАНОВЛЕНИЕ ПОСЛЕ РУЧНОГО ПЕРЕХОДА НА АВТО
Конфликт IPv6 больше не мешает вернуть принадлежащие программе настройки
IPv4, и наоборот. Чужие настройки сохраняются, незавершённый журнал остаётся.
Обычное «Восстановить DNS» возвращает прежние настройки и сообщает о конфликте,
если после включения управления DNS был изменён вручную в Windows.
Явная кнопка «DNS автоматически (DHCP)» принимает уже выбранный автоматический
DNS того же адаптера после проверки. Действующий loopback DNS, незавершённая
системная команда, чужой GUID и повреждённый журнал по-прежнему блокируют сброс.

ОБНОВЛЕНИЕ ИЗ 0.1.10 ПОСЛЕ РУЧНОГО СБРОСА DNS В WINDOWS
Нажмите «Обновить программу», подтвердите обновление и запрос Windows.
Установщик 0.1.11 после остановки принадлежащей службы сохраняет уже выбранный
и проверенный автоматический DNS. Прежний снимок защищённо архивируется в
%PROGRAMDATA%\NetPilot\dns-session.resolved-<идентификатор>.json.
Остальные принадлежащие программе настройки восстанавливаются отдельно.
Установщик не переводит чужой статический DNS на DHCP ради обновления.
После успешного обновления служба работает в режиме наблюдения; управление
DNS выключено. Каналы и история сохраняются.
Если нет кнопки обновления, завершите прежнюю программу через «Выход»
(крестик только прячет окно), распакуйте новую в отдельную папку и запустите её.
«DNS автоматически (DHCP)» остаётся отдельным явным выбором для нужного адаптера.
Повреждённый журнал, незавершённая системная команда, смена DNS во время
восстановления или сторонний статический DNS по-прежнему останавливают обновление.
Не удаляйте dns-session.json и его резервную копию вручную.
Проверки разработки изолированы; восстановление на конкретном Windows 11
этой сборкой ещё требует проверки на самом проблемном компьютере.


ИСПРАВЛЕНИЯ В 0.1.9
Закрытый UDP-клиент больше не останавливает весь локальный DNS-посредник.
«Восстановить DNS» проверяет фактическое состояние после тайм-аута netsh;
если требуется, применяет резервный способ Windows отдельно для IPv4/IPv6.
Ошибка одного семейства не мешает восстановить другое. Сохранённый журнал
позволяет продолжить собственное частичное восстановление после перезапуска.
Сторонние изменения DNS не перезаписываются. DHCP с действующим loopback DNS
не выдаётся за успешное восстановление. Обновите также фоновую службу.
Проверки выполнены на модели адаптера и высоких loopback-портах; работа
восстановления на конкретном ПК Windows 11 ещё требует проверки пользователем.

ЗАПУСК
Распакуйте все файлы в одну папку и запустите RtlineDnsPilot.exe.
Нужен Microsoft .NET Desktop Runtime 10.0 для Windows x64:

ОБНОВЛЕНИЕ С NETPILOT И ПРЕЖНИХ RTLINEDNSPILOT
1. Завершите старую программу через «Выход» в окне или в трее.
2. Распакуйте новую версию в отдельную папку и запустите RtlineDnsPilot.exe.
3. Нажмите «Обновить службу» или «Исправить службу». Подтвердите действие
   и разрешение Windows «Разрешить вносить изменения?» кнопкой «Да».
   Обновление сначала возвращает исходные DNS, затем запускает службу
   в режиме наблюдения. Каналы и история сохраняются.
4. При необходимости включите управление DNS. Если показан сохранённый
   локальный черновик, примените его через «Проверка и сеть».

Для нового компьютера выберите физический Wi-Fi/Ethernet адаптер на
вкладке «Проверка и сеть», затем нажмите «Включить управление DNS».
Установка службы требует разрешения Windows. Обычные проверки — нет.
Не нужно постоянно запускать главное окно от имени администратора.

ЕСЛИ ПРОПАЛА СВЯЗЬ СО СЛУЖБОЙ
Окно само повторяет подключение с задержками 2, 5, 10 и до 30 секунд.
Показаны последний успешный ответ и время следующей попытки.
«Проверить связь» — повторить запрос сейчас, без изменения DNS.
«Исправить службу» — с разрешением Windows остановить службу,
вернуть исходные DNS и заново запустить наблюдение; управление выключено.
«Отключить управление» / «Восстановить DNS» — вернуть исходные DNS.
При недоступной службе для этого используется помощник с разрешением Windows.
Отмена запроса Windows не считается выполнением действия.

Пока служба не отвечает, окно не утверждает, что DNS применён, и не
запускает второй автоматический монитор. Можно выполнить отдельную
разовую локальную проверку — её источник указан в окне.
Неподтверждённая команда изменения настроек не повторяется автоматически.
При сторонней замене DNS или повреждённом журнале восстановление
останавливается с описанием конфликта; журнал сохраняется.

ЧТО ПРОВЕРЯТЬ
Отдельная вкладка: галочки ChatGPT / Codex, Gemini, Tailscale и до шести своих
объектов. Для своего объекта задаются имя и публичный HTTPS URL без
пароля, параметров запроса и фрагмента. Не добавляйте личные URL.
Выберите хотя бы один объект и нажмите «Применить объекты».
По умолчанию выбран только ChatGPT. Для автоматического выбора канала
должны пройти проверки всех включённых объектов. Больше объектов — больше
проверок; одновременно выполняются не более четырёх.
При изменении набора объектов нужны новые измерения. История сохраняется.

Проверяются DNS и публичные HTTPS-страницы без аккаунтов и cookies.
Вход в Codex/Gemini, генерация и WebSocket не проверяются.
Tailscale проверяет только https://login.tailscale.com/: доступность входа,
а не VPN-туннеля, устройств или RDP. По умолчанию галочка выключена.
Документация: https://tailscale.com/docs/reference/faq/firewall-ports
401/403/429 и ошибки сервера не считаются успешной проверкой.
Миллисекунды означают задержку ответа, а не скорость в Мбит/с.

КАНАЛЫ И ГРАФИКИ
Встроены все 15 публичных профилей. Они также есть в profiles.json
для импорта. Свои каналы сохраняются; ранее удалённые встроенные профили
не возвращаются автоматически. DoH URL необязателен: пустое поле — DNS
UDP/TCP. Дубликаты имён, ID, эквивалентных настроек и IP проверяются.
При ошибке DoH приложение не переходит скрыто на открытый DNS.

Правая кнопка по каналу: зафиксировать постоянно, на 5/15/60 минут,
вернуться к автоматическому выбору или удалить канал.
При фиксации автоматическое переключение отключено даже при отказе
канала. По истечении времени возобновляется автоматический выбор.
Синий — активный канал; красный текст сохраняет видимость его ошибок.
Зелёный — свежая успешная проверка остальных, красный — свежий отказ,
серый — нет свежих данных или канал выключен.
В «Журнале» — графики по каналам и события. Неуспешные столбики красные.
Числовая история выбора по-прежнему содержит до 120 измерений.
Для графиков отдельно накапливается архив за 24 часа, по минутам.
В «Журнале» задаются независимо:
- «Период»: за какое время показывать данные, от минут до 1 дня;
- «Один столбик»: сколько минут объединять, например 5 или 15 минут.
Это не частота сетевых проверок; она задаётся на вкладке «Проверка и сеть».
Для суток минимальный столбик — 5 минут (до 300 столбцов на канал).
Пустые интервалы остаются пустыми. Красный столбик — хотя бы один сбой
в интервале; подсказка показывает число проверок и сбоев. Высота — среднее
время DNS + HTTPS. Текущий неполный столбик выделен отдельно.
Карточки идут по успешности за выбранный период, затем по числу измерений,
при равенстве — по средней задержке; каналы без данных идут ниже.
Новый архив при первом запуске заполняется сохранёнными измерениями,
после чего постепенно накапливает сутки. У каждой конфигурации DNS и
набора объектов своя история: чужие данные не превращаются в успехи.
История читается, когда вкладка видима; для графиков новые сетевые пробы
не запускаются. При старой службе нужно выполнить её обновление.
Обычный автоматический переход после отказа требует трёх сбоев подряд
и двух свежих успехов резервного канала. В режиме «Самый стабильный» после пяти
последовательных успехов
и пяти минут удержания приложение выбирает более успешный по измерениям канал,
даже если он медленнее. При равной успешности выигрыш задержки должен быть
не менее 20%. Ручная фиксация и явное предпочтение имеют свои правила.
Доступность провайдера не означает проверку его безопасности.
Адреса и датированные источники перечислены в CHANNELS.txt.

СТРАНА ПОДКЛЮЧЕНИЯ ДЛЯ КАЖДОГО ОБЪЕКТА
На вкладке «Каналы» под активным каналом показана страна, которую каждый
проверяемый сайт явно сообщил об анонимном подключении через этот DNS.
Это не страна DNS-сервера, не страна сервера сайта и не регион аккаунта.
Страна одного объекта не переносится на другие объекты.
Показатель берётся из того же HTTPS-ответа, без дополнительных запросов:
- для HTTPS /cdn-cgi/trace — поле loc, если h совпадает с именем сайта;
- для собственного сайта — один заголовок ответа X-Client-Country с
  двухбуквенным кодом страны (например NL), если сайт его предоставляет.
Для ChatGPT используется его собственный /cdn-cgi/trace. Для Gemini и
прочих сайтов, не выдающих эти данные, показано «Не определена».
Страна не вычисляется по IP сервера, языку страницы или чужому геосервису.
Если измерение устарело или активный канал службы неизвестен, страна
не показывается как подтверждённая. Источник и время — в подсказке.
Отсутствие страны не делает доступный канал красным и не влияет на выбор.
Программа читает не более 4096 байт trace с лимитом 500 мс в пределах
прежнего срока проверки. Сырой ответ и IP пользователя не сохраняются.
Справка Cloudflare о trace:
https://developers.cloudflare.com/fundamentals/reference/cdn-cgi-endpoint/
Регион, используемый авторизованным аккаунтом, может отличаться от
результата анонимной проверки. Информация Google о местоположении Gemini:
https://support.google.com/gemini/answer/13594961

ПАУЗА И ВОССТАНОВЛЕНИЕ
«Пауза проверок» останавливает автоматические проверки и выбор.
Текущая пересылка DNS и настройки адаптера сохраняются.
«Проверить сейчас» выполняет один цикл без снятия паузы.
«Отключить управление» возвращает исходные DNS.
«DNS автоматически (DHCP)» задаёт автоматическое получение DNS на
выбранном физическом адаптере для включённых IPv4/IPv6; требуется
подтверждение и разрешение Windows. Это отличается от восстановления
исходного DNS, который мог быть задан вручную.
Перед изменением создаётся защищённый журнал; частичный сбой вызывает откат.

Управление направляет DNS выбранного адаптера на 127.0.0.1 и, при
включённом IPv6, ::1. Локальная служба пересылает запросы провайдеру.
VPN, прокси, маршруты, IP и привязки протоколов приложение не меняет.
Существующие соединения и кэш других приложений могут задержать эффект
переключения DNS. Закрытие окна прячет его в трей; для выхода есть «Выход».

ДАННЫЕ И СОВМЕСТИМОСТЬ
Для сохранения прежних настроек используются старые внутренние пути:
%LOCALAPPDATA%\NetPilot — локальные настройки и статистика;
%PROGRAMDATA%\NetPilot — данные службы;
%PROGRAMFILES%\NetPilot — защищённые файлы службы.
Имя службы Windows остаётся NetPilotDns. Новое имя программы — RtlineDnsPilot.
Не удаляйте журнал и файлы установленной службы при включённом управлении.

Этот архив содержит только программу, общую инструкцию, публичные
каналы и SHA256. Диагностика компьютера разработчика, его сетевые
настройки, журналы и персональные идентификаторы не включены.
profiles.json содержит публичные профили с ID из публичных параметров.
Отладочные символы и локальные пути сборки не включены.

ПОДЕЛИТЬСЯ DNS — ВЛАДЕЛЬЦУ RTLINEDNSPILOT
Отдельная зелёная кнопка в верхней панели работает одним нажатием.
Приложение отбирает дополнительные каналы вне 15 базовых, с публичными
DNS и успешной проверкой ChatGPT/Gemini за последние 24 часа, ещё
присутствующей в сохранённых измерениях. Если подходящих каналов нет,
показывает сообщение без обращения в сеть.

Получатель один: каталог владельца RtlineDnsPilot. Адрес приёмника уже
встроен; вводить адреса, коды, Google-пароль и разрешать доступ к своему
Диску отправителю не требуется. Старые сохранённые адреса игнорируются.
Нажатие кнопки означает отправку; промежуточной формы подтверждения нет.
Автоматических отправок при запуске, наблюдении или открытии вкладок нет.

Передаются только протокол DNS, публичные адреса, порт, DoH URL и отметки
успешных публичных проверок ChatGPT/Gemini. Имена каналов, ID, примечания,
IP пользователя, сеть, собственные сайты, страны, статистика и журналы
не отправляются. Это пользовательские сообщения о доступности, не
подтверждение безопасности провайдера или авторизованной генерации ИИ.

Результат показывается в строке состояния и журнале. При подтверждённом
успехе видны количества добавленных и уже известных каналов. Дубликаты
приёмник не добавляет. При неизвестном результате нет автоматического
повтора; повторная отправка тех же данных в этой сессии блокируется.
Полученные записи отключены и не включаются в базу программы автоматически.

Приёмник владельца может менять только один созданный им JSON-файл;
остальные пользователи не получают права записи в папку Google Drive.
Включены проверка схемы и адресов, исключение базового набора, дедупликация,
лимиты 10 запросов/минуту, 200/сутки UTC, 100 новых строк/сутки, максимум
1000 строк и 256 КиБ. Публичная отправка без входа не исключает спам и
исчерпание квот Apps Script. Владелец может отключить приёмник.

ИНДИКАТОРЫ И СБОЙ CODEX
Под кнопками отдельно показаны «Проверки» и «DNS». Пауза выделяется жёлтым,
включённое управление DNS — синим, неизвестное состояние подписано явно.
Полоска рядом означает получение состояния/истории или выполнение команды.
Время последнего измерения обновляется после поступления результатов.
Нажатые режимы выделены заливкой и рамкой; мигание кнопок не используется
как индикатор проверки. Во время обычного опроса кнопки остаются доступны.

Успешная публичная проверка ChatGPT не доказывает, что рабочее соединение
Codex не оборвалось. Его WebSocket/TLS, авторизация, кэши и конкретный маршрут
могут вести себя иначе. При успешном HTTP 200 от проверяемой страницы нет
трёх неуспешных раундов и аварийное переключение не запускается. Программа
не читает журналы Codex автоматически и не перехватывает токены аккаунта.
Не обещается восстановление любой ошибки Codex простой сменой DNS.
РЕЖИМ АВТОВЫБОРА (0.1.6)
Нажмите кнопку «Авто» на вкладке «Каналы» и выберите:
- «Самый стабильный»: сначала наибольшая доля успешных проверок,
  при равенстве — меньшая задержка. Это режим по умолчанию и при обновлении.
- «Самый быстрый»: наименьшее среднее время DNS + HTTPS среди каналов,
  которые сейчас проходят все выбранные проверки; при равенстве — успешность.
  Это задержка ответа, а не скорость загрузки в Мбит/с.
Выбор пункта снимает ручную фиксацию и предпочтение, сохраняет выбранный
режим и включает автоматический выбор. Последующие возвраты к «Авто»
используют этот режим. Пауза проверок сама при этом не снимается.

В обоих режимах сохраняется защита от частых переключений: для обычного
перехода нужны пять последовательных успешных раундов резервного канала
и пять минут после последнего переключения. Для перехода ради скорости
нужен выигрыш задержки не менее 20%. В «Самом быстром» успешность за всю
историю может быть ниже, если свежие проверки подтверждают доступность.
Аварийный переход — после трёх отказов к каналу с двумя свежими успехами.
Постоянная ручная фиксация отключает автовыбор; явное предпочтение тоже
имеет свой приоритет. История и накопленные измерения при смене режима
сохраняются, их период/частота не меняются.
Для режима «Самый быстрый» нужна служба 0.1.6 или новее. Если служба старая, программа сохранит
выбор локально и предложит обновить службу, затем применить настройки.
Отдельно установленный приёмник Google Drive обновлять для этого не нужно.
ОТДЕЛЬНАЯ КНОПКА (0.1.7)
«Поделиться DNS» находится в общей верхней панели,
выделена зелёным и доступна с любой вкладки. В 0.1.8 нажатие сразу отправляет подходящие DNS владельцу.
