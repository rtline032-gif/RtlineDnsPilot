RtlineDnsPilot: приёмник владельца для «Поделиться DNS», протокол 2

Получатель программы нажимает «Поделиться DNS». Программа отправляет подходящие
дополнительные DNS на единственный встроенный приёмник владельца. Пользователю
не нужно вводить адрес, приглашение или параметры Google Drive. Новые строки
добавляются в один JSON-файл владельца; повторные настройки не добавляются.

Этот комплект содержит исходники приёмника. Наличие исходников или успешная
локальная проверка с подставными Google-сервисами не подтверждают развёртывание
в аккаунте Google и запись в настоящий Google Drive. Для работы нужен один раз
настроенный и опубликованный приёмник; URL папки Drive не заменяет URL /exec.

Однократная настройка владельцем
1. Создайте отдельный проект на https://script.google.com/ под своим Google-аккаунтом.
   Поместите Code.gs в редактор. В настройках проекта включите показ appsscript.json
   и замените его содержимое файлом из этого комплекта. В разделе «Сервисы» должен
   быть подключён Drive API v3. Для стандартного Cloud-проекта также включите Drive
   API в его Google Cloud Console. Не добавляйте DriveApp или полный доступ Drive.
2. Из редактора запустите setupCatalog и выдайте разрешения drive.file и
   script.external_request. Второе требуется для чтения файла по официальному
   media endpoint Google: Advanced Drive Service не возвращает сырое содержимое.
   В коде URL ограничен API Google и сохранённым ID собственного каталога,
   переадресация запрещена; токен не выводится в журналы и ответы. Полный доступ
   к Google Drive не требуется и не запрашивается.
   Скрипт создаст один файл RtlineDnsPilot-shared-dns.json в «Моём диске»; ссылка
   появится в журнале выполнения. Повторный setupCatalog использует тот же файл
   и всегда выключает публичную отправку до явного enablePublicSubmissions.
   Переместите созданный файл вручную в свою существующую папку DNS через Google
   Drive. Папку и файл оставьте доступными другим только для чтения. Никому не
   выдавайте права редактора папки или Apps Script ради отправки DNS.
   ID папки и ID файла не нужны приложению и не включаются в распространяемый код.
3. Прочитайте ограничения ниже. Чтобы разрешить отправку без приглашений, один раз
   запустите enablePublicSubmissions в редакторе. Эта функция сначала проверяет,
   что собственный каталог существует и корректен. Без явного включения запросы
   протокола 2 отклоняются. Функции владельца недоступны через HTTP.
4. «Развернуть» → «Новое развёртывание» → «Веб-приложение». Выполнять от вашего
   имени; доступ — «Все»/«Anyone», если это разрешено вашим Google-аккаунтом.
   Скопируйте HTTPS URL, заканчивающийся /exec. /dev для пользователей не подходит.
   OAuth-токены и пароль Google владельца никому не передавайте. Если организация
   запрещает анонимные веб-приложения, эта схема в таком аккаунте не работает.
5. Владелец указывает единственный URL /exec при подготовке сборки RtlineDnsPilot.
   В архив для пользователей входит только публичный адрес приёмника. Не входят
   пароль, OAuth-токен, ID каталога или права доступа к другим файлам.
   Получатель архива не настраивает приёмник. Персональные приглашения для него
   не создаются и в публичный архив не помещаются.
6. Откройте /exec в браузере без параметров. Ожидается небольшой JSON:
   {"Service":"RtlineDnsPilot","Protocol":2,"PublicEnabled":true,"Ready":true}
   Это проверка опубликованной версии и её настроек. Она не читает Drive и сама
   по себе не подтверждает доступ к файлу или успешную запись.
7. Сделайте одну пробную отправку подходящего дополнительного канала. Сверьте
   результат приложения с JSON-файлом в Google Drive: должна добавиться одна строка
   с Enabled=false, производными от публичных настроек ID/именем и пометкой
   «Сообщено пользователем; независимо не проверено». Повторная ручная отправка
   должна сообщить дубликат и не изменить файл. Проверьте, что другие файлы папки
   остались без изменений. Это проверка настоящего Drive/API/прав. При ошибке
   не запускайте серию повторных отправок: сначала разберитесь с её причиной.

Что принимает приёмник
Тело POST — JSON с точными полями Protocol:2 и Profiles. В каждом профиле допускаются
только Mode, Servers, DnsPort, DohUrl и WorkedServices. WorkedServices содержит
chatgpt и/или gemini. Приложение выбирает только дополнительные публичные DNS,
у которых сохранён успешный публичный ответ ChatGPT/Gemini за последние 24 часа.
Приёмник принимает факт проверки со слов приложения; сам не обращается к DNS,
сайтам и присланным DoH URL. Злоумышленник может подделать этот факт.

Базовые 15 профилей, локальные/зарезервированные адреса, дубликаты и неизвестные
поля отвергаются. Имена каналов/ПК, IP подключения, заметки, ваши сайты, история
и диагностика в протокол не входят. Google как провайдер HTTP-службы получает
сетевой запрос; это не обещание отсутствия технических данных у Google.

Использование каталога
Каталог — массив профилей ChannelProfile. Записи являются непроверенными
сообщениями пользователей, а не рекомендацией безопасных DNS. Они всегда выключены.
В одном приложении поддерживается максимум 32 канала. Если общий каталог больше,
перед импортом оставьте в отдельной локальной копии только нужные строки, учитывая
уже добавленные каналы. Каталог не подмешивается в базу приложения автоматически.

Ограничения и защита
POST принимает только установленную схему, максимум 96 КиБ и 32 профиля.
Публичный протокол 2 имеет общие для всех пользователей лимиты: 10 запросов
в минуту и 200 за сутки UTC. Запрос с корректной общей схемой расходует лимит
до проверки содержимого профилей и до доступа к Drive; дубликаты и ошибочные
каналы также расходуют лимит. Лишние запросы не читают Drive и не перезаписывают
счётчик. В ScriptProperties хранится один счётчик PUBLIC_REQUESTS; идентификаторов
установок и отдельных записей для каждого отправителя нет.

Не более 100 новых строк за сутки на весь приёмник, включая старый протокол 1;
максимум 1000 строк или 256 КиБ каталога, что наступит раньше. Дубликаты не
перезаписывают файл и не меняют ранее сохранённое описание проверки. Неудачная
или неоднозначная запись может израсходовать лимит без добавления строки.
Записи сериализованы ScriptLock. Клиент не может выбрать файл, папку или команду.
Код пишет только в созданный скриптом каталог с проверенным маркером; папка,
права доступа и другие документы этим HTTP-интерфейсом не изменяются.

Публичный адрес не является секретом. Встроенный код или пароль в распространяемом
приложении также нельзя считать защитой: их можно извлечь. Любой знающий адрес
может отправлять запросы. Ограничения сдерживают рост каталога и число записей
Properties, но не исключают спам, исчерпание квот Apps Script и отказ в обслуживании.
Например, посторонний может первым израсходовать общую суточную квоту приёмника.
Даже запрос, отклонённый до Drive, уже достиг Google и использовал ресурсы Apps Script.
Доступность аккаунта, квоты и региональные ограничения Google могут помешать работе.

Остановка и обновление
Чтобы остановить отправку новых приложений, запустите disablePublicSubmissions
в редакторе. Старый протокол 1 с действующими приглашениями при этом остаётся
доступен. disableReceiver выключает оба протокола и сбрасывает публичный режим.
setupCatalog включает общий приёмник, но публичный режим всегда оставляет
выключенным. Для его возобновления нужен отдельный enablePublicSubmissions.
Включение и выключение не сбрасывают уже израсходованные лимиты и не удаляют файл.

Для полного прекращения публичных обращений откройте «Управление развёртываниями»
и архивируйте/отключите веб-приложение. Каталог и другие файлы это не удаляет.
При изменении кода обновите версию существующего развёртывания, проверьте GET
и одну пробную отправку. Не меняйте публичный URL без новой сборки приложения.

Совместимость со старым протоколом 1
Старые приложения могут продолжать отправлять Protocol:1, InviteCode и Profiles.
createInvite создаёт персональный 256-битный код, показываемый в журнале один раз,
и hash для отзыва. В ScriptProperties хранится только SHA256 hash. На код разрешено
пять аутентифицированных попыток за сутки UTC, включая дубликаты и неверные каналы.
Для отзыва задайте свойство REVOKE_INVITE_HASH и запустите revokeInvite в редакторе.
Эта совместимость не требуется новым пользователям и не даёт HTTP-доступа к
управлению приёмником. Публичный режим по-прежнему включается только владельцем.
